v13.5 2026 年 8 月

取消和进度现在遵循正确的作业

在此版本中

01作业范围的 Socket.IO 进度02真正停止批量和播放列表03单独的安全取消配额

滚动查看发生了什么变化

重叠的作业或延迟取消可能会影响新下载的显示进度。此版本使每个作业都保持在自己的身份和生命周期内。

作业范围的 Socket.IO 进度

队列、下载、完成和错误事件现在带有不可变的 download_id。该接口仅接受其活动作业的消息。

真正停止批量和播放列表

保留活动请求 ID 和 AbortController。 Stop 中止连接，等待有界后端取消，然后才将接口向前移动。

单独的安全取消配额

取消不再与正常的 API 配额竞争，因此在繁忙使用期间不会不必要地阻止停止活动作业。

旧的作业不能再泄漏到新的屏幕中，并且停止按钮现在可以真正发挥作用。
