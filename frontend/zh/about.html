01 / 什么是ZENITHW？

独立的开源媒体工作区。

ZenithW;是一个独立的网络工具，可以分析支持的视频或音频链接，显示可用的质量和格式，准备选定的媒体并将其传送到浏览器。其目的是提供清晰的下载体验，没有虚假的下载按钮、广告重定向和不必要的会员步骤。

该项目不仅仅是下载链接。它将视频和音频格式、批量下载、无损再混合、文件转换、元数据、字幕和处理进度等功能结合在一个简单的界面中。 ZenithW 不是媒体档案或社交网络；它是一个临时工具，用于完成用户期望的操作。

02 / 它是如何运作的？

从连接到交付的受控流程。

发送的链接首先通过安全和支持的平台规则。后端接收来自资源提供者的媒体信息；它使用 yt-dlp 找到合适的流，并在必要时使用 FFmpeg 执行合并、重新复用或转换。进度通过Socket.IO传输到接口。准备好的文件通过定时且一次性的传输链接呈现给同一用户。

事务文件不作为持久内容存储进行维护。成功传输完成后，文件被清除；未完成或错误的作业也会通过定期清洁机制删除。这种设计既限制了磁盘使用，又防止了不必要的媒体积累。

03 / 安全吗？

信任是通过可验证的界限而不是口号建立的。

ZenithW不需要用户账户或支付信息；无意在下载页面上运行广告脚本和第三方跟踪像素。生产流量通过 HTTPS 转发到 Cloudflare，然后从那里转发到仅经过验证的源连接的 Amazon EC2 后端。源 URL 控制、防止访问私有网络地址的 SSRF 保护、文件和时间限制、请求速率限制和临时文件清理等都是后端的防御层。

然而，“零风险”的承诺对于任何在互联网上运行的服务来说都是不诚实的。使用的浏览器、Cloudflare、AWS、源平台和开源组件是单独的信任边界。 ZenithW 并非旨在将私人或敏感连接存储为秘密保险箱。用户应仅处理他们有权访问和下载的内容；他们必须对个人或机密媒体进行自己的风险评估。

04 / 隐私

处理什么、存储什么、提供什么保证？

当发起交易时，连接、技术请求信息和IP地址通过Cloudflare和AWS基础设施来运行服务。 IP地址可能被用于滥用和并发交易限制；出于操作安全目的，可以在基础设施日志中查看错误和访问记录。源平台还强制执行自己的连接和日志策略。

下载历史记录与服务器帐户无关；它保存在浏览器的本地存储中，并且可以从历史页面中删除。准备好的媒体文件不会保存到永久用户配置文件中。 YouTube使用的服务器cookie是站点管理员的技术访问文件；访客的浏览器cookie不会上传到ZenithW。

保密性有保障吗？

无法保证绝对匿名或“不处理任何数据”。该承诺更加具体：旨在不创建不必要的用户帐户，不永久存档媒体文件，将历史记录保留在本地，并且不滥用安全所需的数据。详细和最新的规则以隐私页面为基础。

05 / 您如何信任？

注意你可以控制的事情，而不是所说的。

  • 检查域名： 官方界面只能通过 zenithw.space 和 api.zenithw.space 运行。
  • 查看代码： 源代码、请求流程和安全检查可以在 GitHub 查看。
  • 查询权限： ZenithW 不需要您创建浏览器密码、付款信息或个人帐户即可进行正常下载。
  • 管理本地数据： 您可以随时删除下载历史记录并清除浏览器站点数据。
  • 谨慎对待敏感内容： 请勿向任何在线下载服务发送您无权访问或必须保密的链接。
