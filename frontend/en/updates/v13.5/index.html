v13.5 August 2026

cancellation and progress now follow the correct job

In this release

Scroll to explore what changed

Overlapping jobs or delayed cancellation could affect the progress shown for a newer download. This release keeps every job within its own identity and lifecycle.

job-scoped Socket.IO progress

Queue, download, completion, and error events now carry an immutable download_id. The interface accepts messages only for its active job.

real stopping for bulk and playlists

The active request ID and AbortController are retained. Stop aborts the connection, waits for bounded backend cancellation, and only then moves the interface forward.

a separate safe cancellation quota

Cancellation no longer competes with the normal API quota, so stopping an active job is not needlessly blocked during busy use.

An older job can no longer leak into a newer screen, and the stop button now does real work.
