## ✨ ZenithW を選ぶ理由

ZenithW はメディア作業を落ち着いて分かりやすく保ちます。リンクを貼り、ソースが実際に提供する内容を確認し、適した出力を選んで準備済みファイルを保存します。アカウント、拡張機能、ペイウォール、広告レイヤーはありません。実用的なツールと明確な制限だけです。

- **一つの作業場所**でダウンロード、音声抽出、変換、リマックスを扱えます。
- **プライバシーを考慮した初期設定：**履歴はブラウザ内に残り、準備済みファイルは期限切れになります。
- **正直な設定：**プロファイルは希望であり、すべてのソースにすべての形式があるという約束ではありません。
- **セルフホスト対応：**Docker Compose で UI と API を自分の PC またはサーバー上でまとめて起動できます。🐳

## 機能

- YouTube、TikTok、Instagram、X、Reddit、その他の yt-dlp 対応ソースからメディア情報を取得します。
- 動画、音声、無音動画、再生リスト、小規模なリンクバッチをダウンロードできます。
- FFmpeg で変換し、互換性のあるストリームは不要な再エンコードなしでリマックスします。
- 字幕、メタデータ、サムネイル、SponsorBlock、キャンセル、ライブ進捗表示に対応しています。
- ダウンロード履歴はサーバーアカウントではなくブラウザ内に保持します。
- トルコ語、英語、フランス語、ドイツ語、日本語のレスポンシブでフレームワークを使わない UI を提供します。

ZenithW は短く確認しやすいワークフローを中心に設計されています。対応リンクを貼り付け、メディアの詳細と選択肢を確認してから、ブラウザで直接ダウンロードするファイルを準備します。アカウント、ブラウザ拡張機能、デスクトップクライアントは必要ありません。重要な選択を見せながら、インターフェースは意図的にコンパクトに保たれます。

## ダウンロード設定

ホーム画面では、自動選択、音声抽出、無音動画、再生リスト処理、小規模なリンクバッチを利用できます。複数形式がある場合、開始前にコンテナ、解像度、コーデック設定、音声ビットレート、字幕、メタデータ、サムネイル、ファイル名パターン、SponsorBlock の動作を選択できます。

設定には実用的な 3 種類のダウンロードプロファイルがあります。

- **Minimal** は、すばやい共有と限られたストレージ向けに、小さく幅広く互換性のあるファイルを優先します。
- **Standard** は、バランスの取れた 1080p H.264/MP4 動画と 192 kbps 音声を目標にします。
- **Quality** は、ソースが実際に提供する場合に Opus 音声を含む高解像度 AV1/WebM 動画を優先します。

プロファイルは開始点であり、すべての動画にそのストリームがあるという保証ではありません。YouTube の動画処理では、サーバーが混雑時に 720p の上限を適用し、アイドル時のみ最大 1080p を許可します。形式のフォールバックがその上限を黙って超えることはなく、選択されたストリームの寸法が有効な上限に対して確認されます。音声ダウンロードと YouTube 以外のソースには、それぞれの選択フローがあります。

## メディアツール

ZenithW にはリンクダウンロードに加えて 2 つのローカルファイル用ツールがあります。

- **変換** は、明示的に選択した形式への制限付き FFmpeg 変換のためにファイルをアップロードします。
- **リマックス** は、互換性のある音声・動画ストリームを再エンコードせず新しいコンテナへコピーします。高速で品質低下を避けられますが、互換性のあるストリームでのみ動作します。

どちらも処理状態を表示し、アップロードを保存する代わりに短時間有効な準備済みファイルを返します。アップロードサイズ、出力サイズ、長さ、同時実行数、処理時間はサーバー側で制限されています。

### 端末上での処理 · ベータ

Convert と Remux では、**サーバー**、**この端末を優先**、**この端末のみ**を選べます。ベータ版は互換性のある音声・動画トラックを再エンコードせずにコピーし、コンテナ変更や互換性のある音声の抽出を行います。初期設定はサーバーです。端末で失敗した場合、アップロードには明示的な確認が必要です。「この端末のみ」では送信しません。上限は PC 64 MiB、モバイル・低メモリ端末 24 MiB、30分です。字幕・チャプター・添付データは保持されません。リンクのダウンロードは引き続きサーバーで処理します。[対象範囲・制限・ビルド手順](docs/LOCAL_MEDIA.md)は英語です。

## YouTube の可用性

YouTube のダウンロードはベストエフォートで提供されます。YouTube は、AWS のようなクラウドサーバーを含むデータセンター IP 範囲からのリクエストに、一時的により厳しい確認を適用したりブロックしたりする場合があります。その場合、ZenithW とダウンロードパイプラインが正常でもダウンロード失敗のように見えることがあります。

上流サービスがサーバー IP を制限している間、アプリケーション側の変更だけで中断のない YouTube アクセスを保証することはできません。これは YouTube 対応が削除または無効化されたことを意味しません。改善を監視する間も YouTube ダウンロードは有効のままです。

共有 AWS アドレスへの不要な負荷を減らすため、ZenithW は同じリンクへの同時メタデータ検索をまとめ、短時間キャッシュを使用し、訪問者別・ホスト全体で別々の YouTube リクエスト予算を適用し、重複開始を抑制し、実際の HTTP 429 応答後は追加試行を一時停止します。これらは不要なトラフィックを減らしますが、YouTube 自身のアクセス判断を覆すことはできません。

ZenithW が常に継続的なダウンロードサービスを提供できるとは限らず、YouTube の可用性も常時保証されません。プライバシー設定、地域制限、削除済みコンテンツ、ログイン要件、レート制限は ZenithW の管理外です。

## ユーザー体験とプライバシー

ZenithW は、アカウントなしでライブ進捗、キャンセル、ブラウザローカルの履歴、レスポンシブなデスクトップ・モバイルナビゲーション、多言語対応を提供します。サーバーがファイルを準備するのは転送中だけです。リンクは短時間で失効し、要求元クライアントに紐付き、利用後または期限切れ後に削除されます。

第三者プラットフォームが特定の形式を公開することや、すべてのリクエストを受け入れることは保証されません。ZenithW は利用できない出力を完了済みとして示すのではなく、これらの制限を報告します。

## アーキテクチャ

| レイヤー | 実行環境 |
|---|---|
| フロントエンド | Cloudflare Pages 上の Vanilla HTML、CSS、JavaScript |
| エッジ | Cloudflare DNS、プロキシ、TLS、オリジン検証 |
| バックエンド | Amazon EC2 (AWS) 上の Flask、Gunicorn、gevent、Socket.IO |
| メディア | yt-dlp、FFmpeg、Deno/EJS、任意の PO Token プロバイダー |
| サービス管理 | Ubuntu、Nginx、systemd |

バックエンドは意図的に **単一 worker** で動作します。ジョブ状態、Socket.IO ルーム、準備済みファイルの所有権はプロセスローカルです。worker やレプリカを追加するには、まず共有の調整とストレージが必要です。

## 🐳 Docker Compose でセルフホスト

完全なセットアップには Docker Compose が最も簡単です。フロントエンド、リバースプロキシ、API、FFmpeg、永続ダウンロードボリュームをまとめて起動します。標準構成は意図的に **バックエンド worker を 1 つ**に保ちます。これは現在のプロセスローカルなジョブ、進捗、キャンセル、準備済みファイルの設計に合っています。

```bash
git clone https://github.com/boranseason/zenithw.git
cd zenithw
cp .env.example .env
docker compose up -d --build
```

`http://localhost:8080` を開きます。別のポートや公開ドメインを使う場合は、`.env` の `ZENITHW_PORT` と `SELF_HOSTED_ORIGIN` を一緒に変更し、`docker compose up -d` で再起動してください。

Docker ボリューム `zenithw-downloads` は一時的な処理ファイルを保持します。ZenithW の通常の期限切れクリーンアップは引き続き削除を行います。このボリュームは、コンテナ更新が進行中の転送ウィンドウを不必要に中断しないためのものです。

### 任意のプライベート Cookie

一部のソースではログイン済みブラウザセッションが必要になることがあります。この設定は任意であり、必ず非公開にしてください。

```bash
mkdir -p private
# 自分の Netscape 形式エクスポートを private/cookies.txt に置きます。
cp compose.cookies.example.yml compose.cookies.yml
docker compose -f compose.yml -f compose.cookies.yml up -d
```

`private/cookies.txt` と `compose.cookies.yml` をコミットまたは共有してはいけません。この上書きなしでも ZenithW は動作します。また、これはプラットフォーム制限を回避する万能手段ではありません。

公開運用では Docker の前に HTTPS と任意のファイアウォールまたはリバースプロキシを配置してください。Cloudflare は公式デプロイには便利ですが、セルフホストに **必須ではありません**。

## 🛠️ ローカル開発

必要環境: Python 3.10 以上、FFmpeg、モダンブラウザ。

```bash
git clone https://github.com/boranseason/zenithw.git
cd zenithw/backend
python -m venv .venv
```

環境を有効化してから次を実行します。

```bash
pip install --require-hashes -r requirements.lock
python app.py
```

API は `http://localhost:5000` で起動します。任意の静的ファイルサーバーで `frontend/` を配信してください。開発用 CORS はローカルのクロスオリジン作業でのみ有効化し、本番環境では有効化しないでください。

## 🔐 本番運用の要点

本番環境では `SECRET_KEY` と `ORIGIN_SECRET` に強力な非公開値が必要です。ランタイム制限、信頼するプロキシ、一時ファイルの予算、診断へのアクセスは、`backend/app.py` に記載された環境変数で設定します。

- シークレットとエクスポートしたブラウザデータを Git に入れないでください。
- EC2 オリジンは Cloudflare の背後に置き、共有オリジンヘッダーを検証してください。
- 訪問者ヘッダーは Cloudflare から Nginx へのプロキシチェーン経由でのみ信頼してください。
- 診断情報は非公開にし、公開する生存確認レスポンスは最小限に保ってください。
- ジョブ状態、Socket.IO ルーティング、準備済みファイルを安全に共有できるまで単一 worker を超えてスケールしないでください。

## 主なエンドポイント

| エンドポイント | 目的 |
|---|---|
| `POST /info` | メタデータと形式を解決 |
| `POST /download` | ダウンロードまたは抽出ジョブを開始 |
| `POST /convert` | アップロードしたファイルを変換またはリマックス |
| `POST /cancel` | 実行中のジョブをキャンセル |
| `GET /files/<token>` | 短時間有効な準備済みファイルを転送 |
| `GET /health` | 最小限の生存確認レスポンス |
| `GET /ready` | 依存関係と容量の準備状態 |

## セキュリティと責任ある利用

ZenithW はリモートターゲットを検証し、プライベートおよびリンクローカル宛先をブロックし、リダイレクト、メディアツールのプロトコル、同時実行数、ディスク使用量を制限します。準備済みファイルは短時間有効なトークンで配信されます。絶対的な匿名性や中断のない可用性を約束できるインターネットサービスはありません。

ZenithW は、自分が所有するコンテンツ、ダウンロード許可を得たコンテンツ、または合法的に利用できるコンテンツにのみ使用してください。ソースプラットフォームの規約と著作権ルールは利用者の責任です。ZenithW は対応プラットフォームと提携していません。

再現可能な不具合は [GitHub Issues](https://github.com/boranseason/zenithw/issues) から報告してください。公開レポートにシークレット、非公開リンク、個人データを含めないでください。
